A docs app that renders docs/ with VitePress ​

  • Status: accepted
  • Date: 2026-10-03

Context ​

The architecture, conventions, pipeline, security and decision documents live in docs/ as Markdown, read on GitHub. We want them as a searchable, RTL Hebrew site next to the product site and Storybook, without moving or copying the files: they stay where agents and humans already look for them.

Decision ​

  • apps/docs (project docs, tags type:app scope:product) is a VitePress site whose srcDir is the repo's docs/. It renders the files; it stores no content.
  • It is deployed at /docs/ by tools/pages, next to / (site) and /storybook/. pages:build builds it with site and ui, and assemble.mjs copies it into the artifact. docs/ is a reserved top-level path, and the artifact may never contain a top-level pr-<n>/: the root publish of deploy.yml replaces everything on gh-pages except pr-*/, so previews are untouched and deploy.yml itself did not change.
  • VitePress 2.0.0-alpha.20, pinned. The stable 1.6 line depends on Vite 5 and esbuild 0.21, which add four advisories (one high) to pnpm audit (D1, D2-T). The 2.x line uses the Vite 8 the repo already runs. Revisit when 2.0 is stable; Dependabot does not move a pinned prerelease.
  • Other additions: postcss-rtlcss (the RTL support VitePress documents; the default theme is written for LTR) and vue (the pages VitePress compiles from docs/*.md sit outside apps/docs, so they cannot reach VitePress's own copy; listed in knip.ts).
  • Not an alternative: a React + Vite renderer would reuse more of the stack, but search, syntax highlighting, outline, sidebar and 404 handling are the code we would then own.
  • The app is hand-made, not generated: pnpm new:app creates React/Vite apps. Its Nx build and dev targets are nx:run-commands, so A7 requires them, and the pages:build change, in tools/security/tasks.json (reviewed).
  • The Hebrew UI (navigation, search, labels) is configured in apps/docs/src/labels.ts. The sidebar is built from the files in docs/ (src/sidebar.ts); a new file appears without config. The landing page is docs/index.md. Each block takes the direction of its own text (dir="auto"), because the documents are English and Hebrew prose in one RTL site, and code stays left-to-right.
  • Links from docs/ to files outside it (../tools/...) become links to the file on GitHub (GITHUB_REPOSITORY, or a GitHub origin), or plain text when the repository is unknown. Dead links elsewhere fail the build.

Consequences ​

  • Raw HTML in a document can break the docs build (<stage> at the start of a line is HTML to Vue). src/docs-content.spec.ts names the file and line; put such text in backticks that do not wrap before it.
  • Mermaid blocks render as code; there is no diagram plugin.
  • pipeline-map.md is generated; the docs site shows whatever is committed.
  • The docs content is English, so only the chrome is Hebrew until the documents are translated.
